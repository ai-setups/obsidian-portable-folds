# Portable Folds

标题的折叠状态跟着笔记走——换设备、重启、编辑过后依然还在。

[English](README.md)

## 为什么需要它

Obsidian 把折叠状态按绝对行号存在 `localStorage` 里。只要在标题上方编辑过，行号就对不上了——折叠要么落到别的段落，要么整份丢弃。这份状态也带不出当前这台机器。

## 工作方式

折叠一个标题时，插件会在它的下一行写入一个标记：

```markdown
## 每周记录
%% fold %%

下面的内容处于折叠状态。
```

重新打开笔记时，声明为折叠的标题会自动收起；展开标题则移除标记。全程没有手动步骤——折叠这个动作本身就是保存。

`%% %%` 是 Obsidian 的注释语法，所以标记在阅读视图中不可见。

如果一个标记所属的标题被删除了，它不会去认领后面碰巧出现的标题，而是直接失效。

## 标记为什么独占一行

把标记写在标题行上实现更简单，但它会悄悄破坏链接。

**标题的文本就是它的锚点标识符**，Obsidian 逐字匹配，不会剥离注释。标记追加上去，标识符就会随着每一次折叠而变：

```markdown
折叠时    ## 每周记录 %% fold %%
展开时    ## 每周记录
```

链接是固定字符串，只在写下它的那一刻的折叠状态下有效——这种间歇性故障最难追查。标记放在独立一行，标题文本不受任何改动，锚点也就始终稳定。

## 与 Creases 的区别

[Creases](https://github.com/liamcain/obsidian-creases) 确立了 `%% fold %%` 这个标记。区别在于标记**什么时候**被写下。

Creases 不会自动记录折叠。你折起一个标题，什么都不会保存——必须手动跑命令，也就意味着你得提前判断哪些折叠值得留。不跑，就还是靠行号，行号一变就失效。

Creases 还把标记写在标题行上（`## 标题 %% fold %%`），这会改变锚点标识符，悄悄破坏内部链接。

Portable Folds 在你折叠的那一刻就把标记写在标题下方的独立一行。不需要命令，不需要判断，不破坏链接，没有哪次折叠比另一次更不值得保留。**用户的每一次点击都不会白点。**

## 安装

尚未上架社区插件目录。手动安装时，把 release 中的 `main.js` 和 `manifest.json` 复制到：

```
<vault>/.obsidian/plugins/portable-folds/
```

然后在 设置 → 第三方插件 中启用 **Portable Folds**。

## 已知取舍

- 折叠会写入笔记文件。纳入版本管理的 vault 会在 diff 中看到 `%% fold %%` 这些行。这是状态得以留存的代价；`.gitignore` 无法按行过滤内容。
- 只处理标题。折叠的列表、代码块和 frontmatter 不受影响。
